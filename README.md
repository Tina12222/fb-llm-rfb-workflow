# RAG-Driven Research Workflow for Review Mining and Idea Generation (Code for research paper)

## 📘 Paper Code Overview
This repository contains modular research code for building a structured review-paper database, preparing retrieval resources, running RAG-style retrieval, and supporting LLM-assisted background writing, inspiration extraction, hypothesis generation, and novelty evaluation.

In broad terms, the inputs are raw review-paper text files, reference metadata/abstract collections, and user research queries or motivations. The outputs include structured review databases, retrieval indexes and scores, background text, extracted inspirations, generated hypotheses, novelty assessment files, and evaluation artifacts.

Note: `Reaearch_Idea/` keeps the original directory name for compatibility with existing scripts.
Important: this GitHub repository does not include the text database data. To run the pipelines, users need to prepare their own datasets and place them in the expected input locations.

## ✨ Key Features
- Build a structured review-paper database from raw `.txt` review articles.
- Prepare reference resources through fetching, alignment, deduplication, and abstract extraction pipelines.
- Support chunk-level, theme-level, and hybrid RAG retrieval over the review database.
- Run batch retrieval evaluation scripts and save reproducible result files.
- Generate LLM-assisted background, inspiration, hypothesis, and novelty assessment outputs.
- Use configurable local paths and environment variables instead of requiring a fixed machine layout.

## 🔄 Workflow
1. Build the review database from raw review text in `Review_db/`.
2. Prepare external references in `Reference/` and match citation indices in `ref_db_match/`.
3. Build embeddings, BM25 models, and FAISS indexes for retrieval in `RAG/rag_core/`.
4. Run RAG retrieval and evaluation in `RAG/`.
5. Run the background -> inspiration -> hypothesis -> novelty workflow in `Reaearch_Idea/code/`.

## 🔐 Environment Variables
If you use `.env.example`, the most important variables are:

- `DB_XLSX`: path to the review database spreadsheet used by the retrieval pipeline.
- `REF_XLSX`: path to the reference abstract spreadsheet used for abstract retrieval.
- `RAG_FAISS_DIR`: directory containing FAISS index files for retrieval.
- `RAG_BM25_DIR`: directory containing BM25 model files for retrieval.
- `OPENAI_API_KEY`: API key for LLM-backed scripts that call external model services.

Additional optional variables are listed in `.env.example`, including path overrides for the `Reaearch_Idea/` workflow.

## 🧪 Data Preparation
Prepare the following inputs before running the main pipelines:

This GitHub repository does not include the review-text database or all derived retrieval data. Users need to prepare these datasets locally before running the code.

1. Review text corpus
Put raw review `.txt` files in `Review_db/review_text/`.

2. Review database spreadsheet for retrieval
`RAG/rag_core/main.py` reads `DB_XLSX`, which defaults through `RAG/rag_core/config.py` to:
`Project_root/Review_db/db_change_chunkid_updated.xlsx`

3. Reference abstract spreadsheet for abstract retrieval
`RAG/rag_core/main.py` reads `REF_XLSX`, which defaults through `RAG/rag_core/config.py` to:
`Project_root/Reference/dedup_ref_abstract_del.xlsx`

4. Retrieval artifacts
BM25 and FAISS files are expected under `.rag/` or env-overridden locations, for example:
- `.rag/faiss_index/connected/*.index`
- `.rag/BM25_model/connected/*.pkl`

5. LLM workflow inputs
The idea-generation workflow expects retrieval artifacts plus intermediate files such as background text, inspiration files, and novelty result JSON files generated by earlier steps.

## 🚀 Quick Start
### Check environment
Run the basic non-destructive checks first:

```bash
python run_pipeline.py check --dry-run
python run_pipeline.py rag --dry-run
python run_pipeline.py reference --dry-run
python run_pipeline.py idea --dry-run
python ref_db_match/script/ra_main.py --dry-run
```

### Build review database
Place raw review text files in `Review_db/review_text/`, then run:

```bash
cd Review_db
python main_review.py --input_root review_text --workspace .
```

This command resolves paths relative to `Review_db/` and produces `review_database.pkl`, `review_database.csv`, and intermediate folders such as `sections/`, `chunks/`, `statements/`, and `themes/`.

### Run RAG retrieval
After preparing `DB_XLSX`, `REF_XLSX`, and the BM25/FAISS artifacts:

```bash
python -m RAG.rag_core.main --query "your research question" --top-k 5
```

If your local paths differ from the defaults, configure `.env` or set variables such as `DB_XLSX`, `REF_XLSX`, `RAG_FAISS_DIR`, and `RAG_BM25_DIR`.

### Run evaluation
The evaluation scripts expect an input Excel file with a `query` column:

```bash
python RAG/evaluation/CHUNK_SEARCH.py --input path/to/query_file.xlsx
python RAG/evaluation/chunk_only.py --input path/to/query_file.xlsx
python RAG/evaluation/theme_only.py --input path/to/query_file.xlsx
```

### Run idea generation workflow
The current workflow is modular and should be run step by step:

```bash
python -m Reaearch_Idea.code.background --workspace default
python -m Reaearch_Idea.code.inspiration_generation --workspace default
python -m Reaearch_Idea.code.hypothesis_generation --workspace default
python -m Reaearch_Idea.code.novelty_evaluate --workspace default --round 2
python -m Reaearch_Idea.code.idea_updata --workspace default --round 2
```

These scripts depend on prepared retrieval artifacts, spreadsheet inputs, local path configuration, and available LLM API access.
Some filenames keep their original spelling for compatibility with the existing workflow, including `Reaearch_Idea/` and `idea_updata.py`.

## 🧩 Main Scripts
| Module / Script | Purpose | Typical input | Typical output |
|---|---|---|---|
| `Review_db/main_review.py` | Build the structured review database from raw review text | `Review_db/review_text/*.txt` | `review_database.pkl`, `review_database.csv`, intermediate processing folders |
| `Reference/scripts/ref_main.py` | Build and enrich external reference resources | Review metadata JSON/YAML and pipeline config | Merged, deduplicated, and abstract-enriched reference files |
| `ref_db_match/script/ra_main.py` | Match citation indices back to DOI/metadata and write results to Excel | Input Excel, reference DB JSON, config YAML | Matched JSON folders and updated Excel content |
| `RAG/rag_core/main.py` | Run the main retrieval pipeline for a user query | Query text, review/reference spreadsheets, BM25/FAISS artifacts | Ranked retrieval results in console/log output |
| `RAG/evaluation/CHUNK_SEARCH.py` | Run hybrid retrieval evaluation on batch queries | Excel with `query` column | Result Excel and retrieval log |
| `Reaearch_Idea/code/background.py` | Generate background text from retrieved review content | DB/index artifacts and a user query | `background_<workspace>.txt` and logs |
| `Reaearch_Idea/code/inspiration_generation.py` | Extract inspirations from an abstract corpus | Background text and abstract spreadsheet | Inspiration `.txt/.json` files |
| `Reaearch_Idea/code/hypothesis_generation.py` | Generate hypotheses from inspirations | Background text, inspiration JSON, user motivation | Hypothesis `.txt/.json` files |
| `Reaearch_Idea/code/novelty_evaluate.py` | Evaluate novelty and feasibility using retrieved abstracts | Idea JSON, reference data, retrieval artifacts | `novelty_judgement_results_round*.json` |


## 📂 Outputs
Typical outputs include:

- Structured datasets: `.pkl`, `.csv`, `.xlsx`
- Retrieval resources: `.index`, `.pkl`, mapping `.csv`
- LLM-generated artifacts: `.txt`, `.json`
- Evaluation artifacts: result spreadsheets, logs, and some figure files

Common output locations include `Review_db/`, `.rag/`, `RAG/retrieval/`, `Reaearch_Idea/test/<workspace>/`, and configured folders under `Reference/` and `ref_db_match/`.

## ⚠️ Notes and Limitations
- This is modular research code and may require multiple scripts rather than a single end-to-end command.
- This GitHub repository does not include the text database data, so users must prepare their own datasets locally before running the pipelines.
- Large datasets, retrieval indexes, API keys, cookies, and private research assets should not be committed to GitHub.
- Results may depend on the selected LLM API, embedding model (`BAAI/bge-m3`), local environment, and path configuration.
- Some scripts still rely on user-provided local spreadsheets and intermediate artifacts.
- The exact final paper experiment parameters should be documented after publication.
